Reading a `.urna` no longer links C: zstd text sections, trained-dictionary streams and `urna scalars` `.zst` inputs are decoded by urna's own zstd decoder (RFC 8878, safe Rust, with a hard output limit). The `zstd` crate stays only for writing, behind the new default `write` feature of `urna-format`; `urna-engine` and `urna-cbinds` build without it, so `cargo tree -p urna-engine -e normal` lists no `zstd-sys`.
