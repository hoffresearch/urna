`urna-format` converts f16 and computes SHA-256 itself and writes its records field by field, so `half`, `bytemuck` and `sha2` left the build; the SHA-256 runs on SHA-NI or the ARMv8 SHA2 extension when the CPU has them, and `rust/format/parity` holds both conversions and the hash to the crates they replaced. A breaking change of the Rust API (the file format does not change by a byte): `quantize_f32_to_i4` returns `urna_format::F16` scales instead of `half::f16`, `UrnaHeader`, `SectionEntry` and `UrnaFooter` trade `as_bytes`/`as_bytes_mut` for `to_bytes` and `from_bytes`, `Int8EmbeddingsView::row` becomes `row_bytes` (the stored bytes, each an i8 code; `urna_engine::simd::dot_f32_i8_bytes` scores them), and hashing goes through `urna_format::Sha256` (`new`, `update`, `finalize`, `digest`, returning `[u8; 32]`).
