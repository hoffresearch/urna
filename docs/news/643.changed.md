`urna-format` converts f16 and computes SHA-256 itself and writes its records field by field, so `half`, `bytemuck` and `sha2` left the build; the SHA-256 runs on SHA-NI or the ARMv8 SHA2 extension when the CPU has them, and `rust/format/parity` holds both conversions and the hash to the crates they replaced. A breaking change of the Rust API (the file format does not change by a byte): `quantize_f32_to_i4` returns `urna_format::F16` scales instead of `half::f16`, `UrnaHeader`, `SectionEntry` and `UrnaFooter` trade `as_bytes`/`as_bytes_mut` for `to_bytes` and `from_bytes`, `Int8EmbeddingsView::row` becomes `row_bytes` (the stored bytes, each an i8 code; `urna_engine::simd::dot_f32_i8_bytes` scores them), and hashing goes through `urna_format::Sha256` (`new`, `update`, `finalize`, `digest`, returning `[u8; 32]`). `memmap2` left too: `urna_engine::Mapping` maps a file read-only with `mmap` on unix and `MapViewOfFile` on windows. `urna setup` unpacks the payload and uv through the system `tar`, as it downloads through the system `curl` (bsdtar, in `System32` on windows 10 and later, reads uv's `.zip`), after listing the archive and refusing any entry that would leave the install dir or is a link, so `tar` and `zip` left the build. The kitty and PNG images of `urna tui` are zlib streams of stored deflate blocks, so `flate2` left as well; they are larger on the wire, the same pixels on screen. The `urna` binary carries its own error type, so `anyhow` left its manifest; an error prints the same lines as before, `Caused by:` and all. The engine benches run on a harness of their own (warm-up, p50 and p95), so `criterion` left the dev dependencies. The codec property tests draw their inputs from a seeded splitmix64 (`URNA_PROP_CASES`, `URNA_PROP_SEED`), so `proptest` left too.
