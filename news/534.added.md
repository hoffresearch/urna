`urna setup` offers every model preset, each with a validated install (#534, part of #535): `minilm-multilingual`, four new text models (`harrier-270m`, `jina-v5-text-nano`, `qwen3-embedding-0.6b`, `octen-embedding-0.6b`), `clip-vit-b32`, `siglip2`, `jina-v5-omni-nano`, `jina-v5-omni-small` and `wemm-2b`. Each `InstallSpec` (pinned revision, the exact files, the `model_hash` they fingerprint to) was recorded from an install from an empty cache that then answered a query offline; the files are the ones the loader opens from the snapshot, measured, not listed by hand. The siglip2 hash is the mtg build's and the clip hash a load by tag's, so their corpora keep answering. The repo code of the three jina v5 models was reviewed and pinned (5, 4 and 2 files) and wemm-2b's pins match the revision its install pins; the jina models load their task adapters from the snapshot through `peft`. The offered models' packages are resolved together into one lock, `urna/model/modellock.txt` (`uv pip compile --universal --torch-backend cpu`: Linux, macOS and Windows, torch's CPU build, no `nvidia-*`), shipped in the payload; setup installs a model's packages constrained by it (`uv pip install --torch-backend cpu -c`, pip with PyTorch's CPU index), since PyPI has no `+cpu` torch. After the fetch, setup loads the model through `presetqry.py` and embeds one query with downloads off; from the explorer, the hash it loads as must be the corpus's, which for a sentence-transformers backend model names the dtype of this device. That dtype is the device class's (float16 on MPS, bfloat16 there for `harrier-270m`, float32 on the CPU, bfloat16 on CUDA), so a corpus built with one of those presets on an Apple-silicon Mac is refused on a CPU machine and vice versa, with both hashes shown; potion, `minilm-multilingual` and the open_clip presets are not affected. The model screen scrolls, one line per model: its download with torch counted once, its estimated minimum RAM (parameters from the safetensors headers times the bytes of the dtype it loads in on this device, plus torch's own memory, rounded up to a whole GB) with a ✓ against this machine's RAM (sysinfo), and its license, "non-commercial use only" for CC-BY-NC-4.0; the details of the model at the cursor sit below, potion heads the list as installed, and on an Intel Mac, where torch ships no build, no model can be chosen. `installer.py` verifies an open_clip model by loading it. `tool/tasks/upstreams.py` writes the lock, the torch size per platform and each model's parameter count; `catalogue.py --check` refuses, offline, a lock for other packages or other bytes and a count at another revision. `.github/workflows/presetjob.yml` runs `tool/tasks/presetjob.py` on four platforms when the lock changes: every preset through `urna setup`, each from an empty cache and asked one query, then torch's memory against the catalogue's. On the Mac runner, a VM whose Metal reports MPS available but cannot compile torch's kernels, the script probes MPS after the first install and runs every preset on the CPU (`URNA_ST_DEVICE=cpu`) when the probe fails.
