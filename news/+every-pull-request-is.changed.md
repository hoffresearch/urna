Every pull request is tied to an issue, written down in CONTRIBUTING and the pull request template: one coherent change is one issue and one PR; several independent items are an epic with one GitHub sub-issue each, each with its PR. Issues and PRs get the right label (created when missing), and the milestone and project views once the repository has them. A PR starts with `Closes #<sub-issue>. Part of #<epic>.`, opens from the updated `main`, and lists its checks as checkboxes with results and the tested commit. When a series closes, the epic body becomes its history.
