`urna setup` runs on a clean machine, on a Python torch supports (#529, part of #535). With no uv and no Python it stopped at "no uv and no python3 on PATH"; it now downloads the uv release the payload's catalogue names into `<data root>/urna/bin/uv` through `curl` and refuses it unless its SHA256 is the catalogue's. The env is built with `uv venv --python ">=3.10,<3.15"`, the minors torch 2.14.1 has wheels for, where it used to take the newest interpreter: on a Mac with Python 3.15 every model beyond potion failed on torch. uv takes a matching interpreter on the machine or fetches one; an env on a Python outside the range is deleted and built again, and the models whose weights are cached get their packages back. Without uv, pip runs from an interpreter inside the range, and when there is none the step names the fix in one line. Neither value is written by hand: `tool/tasks/upstreams.py` reads uv's latest release (with the `.sha256` it publishes for each of urna's five platforms) and the range from the names of torch's wheels on PyPI into `upstreams.json`, `catalogue.py` copies it into `catalogue.json`, `--check` stays offline and refuses a catalogue that differs, and `--check` of `upstreams.py` fails when an upstream moved. On macOS, `/usr/bin/python3` is never run while `xcode-select -p` fails: it is Apple's stub and opens the Command Line Tools installer, and setup's scan, `urna doctor` and the embedder fallback of `ask` ran it. uv ran it too: its interpreter discovery runs every `python3` on PATH, and after fetching a Python it runs `install_name_tool`, the same shim; on a Mac without the tools setup now runs uv with `/usr/bin` off its PATH (uv then skips the dylib patch with a warning, which only matters to native extensions built against libpython). The clean macOS VM found this one: the dialog opened with every other check green. A failed package install shows uv's error whole (from its `error:` line, or the `×` of a resolver failure, to the end) where it showed the last line, the hint, cut to two lines. A failed model leaves the run ready: "urna is ready" with the model's error as a warning, not "setup finished with problems" over every verify row `[ ok ]`; the exit code stays `15`. `--uninstall` removes setup's uv too. `tool/tasks/cleanhost.sh` runs the installer and `urna setup --model minilm-multilingual` on a machine with nothing installed, in a Debian container (`linux`) or a disposable vanilla macOS VM through tart (`macos`, with `--control` proving the check sees the stub's dialog); `.github/workflows/cleanhost.yml` runs the container leg and a runner whose newest Python is 3.15. The Windows uv archive is a `.zip`, read with the `zip` crate (deflate only, Windows builds only). `tool/tests/test_upstreams.py` (5 cases) and new cases in the setup unit and end-to-end tests.
