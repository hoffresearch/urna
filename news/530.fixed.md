A binary built from `main` can install a payload (#530, part of #535). It reported 0.5.4, the last release, so `urna setup` fetched the 0.5.4 payload, whose layout setup already refuses; inside the checkout this did not show, since verify and `ask` found the checkout's scripts first. `rust/clitui/build.rs` now decides release or development from the tag, never from a value kept by hand: the release build jobs set `URNA_RELEASE_TAG` (`.github/buildprep.yml`, through dist's `github-build-setup`) and a tag that is not `v` followed by the crate version fails the build; a build from crates.io, which has no `rust/bridge/python` beside it, is a release too. Any other build from a checkout is a development build named `<version>+dev.<sha>` (vergen-gitcl 9.1, whose MSRV matches the crate's 1.88), or `<version>+dev` without `.git`, in `--version`, `urna doctor` and setup's screens. The name is not `git describe`: the release tags up to v0.5.4 sit on commits outside `main`'s history, so describe named today's `main` after v0.2.0, and a `cargo install --git` checkout carries no tags. A development build installs the payload of its own checkout: the required files copied, stamped with its name, and laid down through the same restorable swap as a tarball. When the checkout holds only the LFS pointer of the potion table, the table comes from Hugging Face at the revision `tool/tasks/getpotion.sh` pins, accepted only when its SHA256 is the pointer's oid; a moved or deleted checkout stops setup with its path and the `cargo install` that fixes it (exit 14). `--version` and `URNA_RELEASE_BASE` still fetch a release payload, so `cleanhost.sh`, the rehearsal and `setup_e2e.rs` keep their mirror. Setup's verify runs the doctor checks on the payload in its own data dir, with a `payload` row, whatever the current directory resolves. `[urna] embedder interpreter` is printed only when the interpreter came from the `.venv` search. `gatecheck.yml` fails a CI build that does not name itself a development build, and the rehearsal's binary check accepts the development name of the version.
