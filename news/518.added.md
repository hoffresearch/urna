It ignores one finding by name: `release.yml` and `rehearsal.yml` read `steps.cargo-cyclonedx.output.paths` where the step has `outputs`, so the SBOM path comes out empty; the line is cargo-dist's template and neither file is hand-edited, so the fix belongs upstream. zizmor (1.30.1, through `zizmor-action`) audits the workflows for security. Once #519 brought its findings to zero (#518), any finding fails the pull request, forks included, with an annotation on the line; every pull request runs both jobs, since the ruleset requires them and a path filter would leave a required check waiting; on `main` zizmor uploads SARIF to code scanning, which closes the alerts a merge fixed. Both run locally too: `actionlint` and `zizmor .` from the root.
